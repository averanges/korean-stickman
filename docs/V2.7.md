# Korean Stickman V2.7 — подготовка нескольких STT-серверов

Статус: **подготовка к развёртыванию завершена; весь этап V2.7 пока не принят**. Альтернативных развёрнутых адресов у владельца нет. Ни Netlify, ни Vercel не публиковались. Успешное настоящее STT на альтернативном сервере ещё нужно подтвердить. Публикация GitHub Pages и обновление Render также не выполнялись.

## Что готово

GitHub Pages загружает игру самостоятельно. Render остаётся сервером по умолчанию. Netlify Functions и Vercel Functions подготовлены как дополнительные варианты. Пока их публичные адреса пустые, в панели написано «Не настроен» и запросов к ним нет.

Общий обработчик `server/api.mjs` использует прежний Groq Whisper из `server/stt.mjs`. Render подключается через Node HTTP, функции — через небольшие адаптеры Web Request/Response. Бизнес-логика, запись и обработка корейского/русского языка общие. Сохранены `/api/stt/status` и `/api/stt`, добавлены `/health` и `/transcribe`.

Ручное начало/завершение записи, паузы, языки ko/ru, герой, комната и localStorage сохранены. Автоматического выбора самого быстрого сервера, failover и повторной отправки аудио нет. Проверка готовности при открытии из V2.6 остаётся ограниченной; нового периодического опроса нет.

## Панель «Серверы STT»

Откройте «Настройки голоса / тестирование». При первом открытии панель независимо проверяет настроенные серверы. Кнопка «Проверить серверы» повторяет только проверку доступности. Видны адрес, HTTP, время ответа, время последней проверки, версия API и сборки либо причина ошибки. Медленный сервер не задерживает появление остальных результатов.

«Сервер обычных голосовых команд» выбирается вручную. Выбор не меняет сохранения и не переносит текущую запись на другой сервер. Во время обычной записи, обработки и ожидания повторной отправки выбор заблокирован. Снятый флажок отключает сервер; автоматической замены нет.

В отдельном тесте запись отправляется только выбранному серверу. Даже текст «Создай стол» ничего не создаёт: тест не подключён к игровым обработчикам. После успешного STT аудио остаётся в памяти вкладки. Чтобы сравнить тот же файл, выберите другой сервер теста и нажмите «Отправить ту же запись выбранному серверу». После сетевой ошибки файл тоже сохраняется для явной повторной отправки. «Удалить / отменить запись», новая запись и закрытие вкладки удаляют образец. На сервере приложение аудио не сохраняет; для распознавания оно передаётся Groq.

Поля «Адреса серверов» действуют только до перезагрузки. Для постоянной настройки используются публичные переменные сборки Pages: `API_BASE_URL`, `NETLIFY_API_BASE_URL`, `VERCEL_API_BASE_URL`. Другой вариант — централизованные константы `src/api-config.js` и `src/stt-servers.js`. Только HTTPS-адрес источника без пути, параметров и ключей. Незаданные альтернативы остаются пустыми.

Локальный запуск обычных команд Render использует локальный `/api/stt`, и фактический адрес подписан в панели. Таблица доступности и отдельный диагностический тест проверяют именно публичные адреса. При CORS, разрешающем только GitHub Pages, их нужно проверять со страницы Pages, а не с localhost. Ошибка из локальной вкладки не доказывает общий отказ сервера.

## Обновление Render

1. Загрузите подготовленные исходники в свой репозиторий и обновите существующий Render Web Service.
2. Root Directory — папка с `package.json` (если игра лежит в корне репозитория, оставить пустым).
3. Build Command: `npm ci`. Start Command: `npm start`. Node.js 24.
4. Установите `GROQ_API_KEY` в секретных переменных Render. `FRONTEND_ORIGIN` — источник вашей страницы GitHub Pages, без `/korean-stickman/`. Не копируйте ключ в репозиторий или клиентские поля.
5. Необязательные переменные: `STT_MODEL`, `PUBLIC_ORIGIN`. Render автоматически предоставляет `RENDER_EXTERNAL_URL` и `PORT`; порт вручную задавать не требуется.
6. Health Check Path можно поставить `/health`. Успешный health подтверждает доступность приложения и наличие ключа, но не пригодность ключа или ответ Groq.

Локально по-прежнему `npm ci`, затем `npm run dev` и http://localhost:5173/. Если старый процесс запущен, остановите его в его терминале и запустите заново, чтобы обновился серверный код.

## Netlify Functions

1. Создайте проект Netlify из того же репозитория. Base Directory — папка игры, если она не в корне.
2. `netlify.toml` задаёт Build Command `npm run build:backend`, Publish Directory `backend-public`, Functions Directory `netlify/functions`, Node 24 и сборщик esbuild. Новые зависимости не нужны.
3. Переменные функций: `GROQ_API_KEY`, `FRONTEND_ORIGIN`; необязательная `STT_MODEL`. Убедитесь, что переменные доступны функциям, а не только шагу сборки.
4. Публичный адрес берётся из штатной переменной Netlify `URL`. Для собственного домена можно явно установить `API_PUBLIC_ORIGIN` как точный HTTPS-источник без пути. После изменения переменных пересоберите/разверните проект.
5. Проверьте `/health`: должны быть HTTP 200, `ok: true`, `configured: true`, `apiVersion: "1"`, `platform: "netlify"`, `version: "2.7.0"`. Затем отдельно выполните STT с Pages.

Функция подключает общий код; конфигурация маршрутов обслуживает и новые, и прежние пути. Статическая публикация backend содержит только техническую страницу, не игру и не исходники.

## Vercel Functions

Vercel Hobby разрешён для личного некоммерческого использования. Если игра используется в коммерческих занятиях, Hobby нельзя считать подходящим вариантом: выберите соответствующий платный план или другой хостинг. Условия: https://vercel.com/docs/plans/hobby

1. Создайте Vercel Project из того же репозитория, Root Directory — папка игры.
2. Framework Preset — Other. Node 24. `vercel.json` задаёт Build Command `npm run build:backend`, Output Directory `backend-public`, маршруты и максимальную длительность функций 60 секунд.
3. Переменные: `GROQ_API_KEY`, `FRONTEND_ORIGIN`; необязательные `STT_MODEL` и `API_PUBLIC_ORIGIN`. Без последней используется штатный `VERCEL_PROJECT_PRODUCTION_URL` либо `VERCEL_URL`. Для домена, отличного от этих адресов, явно задайте `API_PUBLIC_ORIGIN`.
4. Пересоберите/разверните проект и проверьте `/health` по схеме выше, с `platform: "vercel"`. Для браузерного вызова API публичный домен должен быть доступен без страницы входа платформы; защищённые preview не подходят для прямого STT из Pages.

## Подключение адресов к GitHub Pages

1. В репозитории → Settings → Secrets and variables → Actions → Variables добавьте публичный адрес альтернативы в `NETLIFY_API_BASE_URL` или `VERCEL_API_BASE_URL` после её настоящего развёртывания. `API_BASE_URL` остаётся адресом Render.
2. Это публичные адреса, не секреты. `GROQ_API_KEY` в переменных frontend не нужен.
3. Pages → Source: GitHub Actions. Запустите существующий workflow Publish frontend to GitHub Pages. Он проверяет тесты и публикует только `dist`.
4. Откройте https://averanges.github.io/korean-stickman/, обновите страницу, проверьте панель и реальное STT. Относительные пути ресурсов сохраняют размещение `/korean-stickman/`.

CORS разрешает только точный `FRONTEND_ORIGIN`, собственный источник API и локальное одноимённое приложение. Для текущей Pages источник — `https://averanges.github.io`, без пути репозитория. Нет `*`, cookies или доверия произвольному forwarded Host. Поддержаны OPTIONS и необходимые заголовки. CORS не является аутентификацией: произвольный внешний HTTP-клиент может обращаться к публичному API.

## Ограничения и защита

| Сервер | Лимит приложения на файл | Длительность записи | Бюджет обработки приложения |
|---|---:|---:|---:|
| Render / локальный Node | 20 МиБ | без отдельного лимита времени записи | 60 с |
| Netlify | 4 000 000 байт | 5 минут | 50 с |
| Vercel | 4 000 000 байт | 5 минут | 50 с |

Пять минут — политика приложения, а не обещанная длительность записи платформы. Паузы не вырезаются. При превышении ограничений отправка не начинается; нет автоматической обрезки, конвертации или переотправки. После сетевого сбоя пользователь решает, повторять ли запрос: предыдущий сервер уже мог вызвать Groq.

Для Netlify документированы 60 секунд синхронного выполнения и 6 МБ буферизованного запроса; при двоичных данных base64 уменьшает полезный предел примерно до 4,5 МБ. Для Vercel ограничение тела запроса/ответа — 4,5 МБ; длительность зависит от режима и плана. Наши 4 000 000 байт и 50 секунд оставляют запас. Большой запрос платформа может отклонить ещё до нашего обработчика; клиент обрабатывает и не-JSON HTTP 413/504, а при недоступных заголовках показывает сетевую ошибку.

Официальные ограничения: https://docs.netlify.com/build/functions/configuration/ и https://vercel.com/docs/functions/limitations . Поддержка адаптера Vercel Request/Response: https://vercel.com/docs/functions/runtimes/node-js . Ограничения проверены 2 ноября 2026; сборка на самих платформах пока не выполнялась.

Сохраняются максимум два одновременных STT-запроса и двадцать запусков за минуту **на экземпляр процесса/функции**. Это простая локальная защита, не общий лимит на все масштабируемые экземпляры. Базы данных, авторизации и распределённого счётчика не добавлено. Учитывайте также лимиты аккаунта Groq и выбранного тарифа хостинга.

## Проверки и фактический результат

Общий прогон: **134 теста, все прошли**. Выполнены сборки frontend и технической страницы backend, проверка состава архива.

- Автоматические проверки адаптеров используют подставной Groq: полное двоичное аудио ko/ru, единый ответ, CORS/OPTIONS, лимиты размера и времени, ошибки и освобождение слотов. Это не настоящее распознавание.
- Проверены реальные локальные Node HTTP-маршруты, совместимость прежних путей, API-only режим, запрет секретных/серверных файлов, корректный 413 для слишком большого потокового запроса.
- Проверены независимые параллельные health-проверки, пустые/отключённые серверы, HTTP-ошибки, невалидные ответы, тайм-аут и запоздалые ответы; выбор сервера не меняется.
- Проверены ручная запись с четырьмя секундами тишины, отмена, явная отправка того же файла другому серверу и отсутствие игровых действий в диагностике. Запись и микрофон в этих тестах подставные.
- Проверены сборка Pages, относительные ресурсы, отсутствие серверных файлов в frontend и отсутствие секретов в поставке. Старые тесты обоих уровней включены в общий прогон.
- В браузере локальная игра открылась, профиль сохранился, незаданные альтернативы показаны как «Не настроен». Публичный Render из локальной диагностической вкладки не дал HTTP-ответа за 20 секунд; это наблюдение этой среды, а не подтверждённый общий отказ Render или тест Groq.
- Настоящие STT-запросы к Groq на Netlify/Vercel, мобильные браузеры, реальные холодные старты и сборки в облаке не проверены. Критерий успешного альтернативного STT пока не выполнен.

## Исправление маршрутов Netlify после деплоя

Публичный адрес, предоставленный владельцем: https://incandescent-lollipop-01828a.netlify.app . Описанный выше статус отсутствия альтернатив относится к первоначальной подготовке, до пользовательского деплоя. Vercel уже исправлен владельцем; его код и переменные этим изменением не затрагиваются.

Причина `not-found`: стандартная функция Netlify получает `(request, context)`. Ранее её default export напрямую ссылался на общий обработчик, у которого второй аргумент — необязательный pathname. Служебный объект Context заменял путь запроса, и проверка списка разрешённых путей всегда возвращала 404. Это воспроизведено тестом реальной точки входа: до исправления `/health` давал 404, после — 200.

В `netlify/functions/stt.mjs` добавлена обёртка `request => handler(request)`. Общий API теперь берёт pathname из `request.url`. `netlify.toml` не содержит rewrite-правил; custom routes уже заданы в `config.path` функции. Дополнительные rewrites и изменение общего API не требуются. Прямой инфраструктурный путь `/.netlify/functions/stt` не является health-маршрутом; его 404 не следует использовать как проверку готовности.

Изменён только runtime-файл Netlify; добавлены `tests/platform-routes.test.js` и это дополнение к отчёту. Игровая логика, STT, Origin/CORS, общий сервер и маршруты Render не изменялись.

Новые тесты вызывают экспортируемые точки входа платформ с аргументами, соответствующими runtime, а не только общий обработчик. Проверены Netlify Context, оба health-пути, query string, оба STT-пути, OPTIONS, запрет постороннего Origin; для Vercel — реальные entry points и rewrite-пути со штатным hostname без схемы. В тестах STT без ключа ожидается безопасный 503 `not-configured`: настоящий Groq не вызывается. Полный прогон — **136 тестов, все прошли**.

Чтобы применить: обновите файл `netlify/functions/stt.mjs` в GitHub и дождитесь нового Netlify deploy (или запустите повторный deploy после загрузки исправленных исходников). Проверьте https://incandescent-lollipop-01828a.netlify.app/health и https://incandescent-lollipop-01828a.netlify.app/api/stt/status : ожидаются HTTP 200, `ok: true`, `platform: "netlify"`. Для настроенного ключа также `configured: true`. Переменные окружения менять из-за этого исправления не нужно.

Облачная публикация исправления не выполнялась. Прямую HTTP-проверку предоставленного домена из среды Codex выполнить не удалось из-за ошибки сетевого доступа; это не подтверждение отказа сервера. Реальный HTTP 200 после повторного деплоя пока не подтверждён.

Документация сигнатуры Netlify: https://docs.netlify.com/build/functions/get-started/ .
