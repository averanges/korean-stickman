# Amvera — ручное подключение STT к Korean Stickman

Amvera добавлена четвёртой строкой в диагностику, в основной ручной выбор сервера и в отдельный «Тест STT без игровых действий».

Адрес: `https://korean-stickman-averanges.msk1.amvera.tech`.
Аудио отправляется на `/transcribe`, проверка — на `/health`.

## Что подготовлено

- Готовность Amvera проверяется через `upstream.sttReady`, `upstream.reachable` и успешный HTTP-код Vercel. Верхнего `ok:true` недостаточно. Работающий прокси с недоступным Vercel показывается как «STT недоступен».
- В отчёте сохраняются адрес Amvera, HTTP-код и время проверки, состояние Vercel, `sttReady`, ошибка upstream, результат распознавания и ошибки аудиозапроса.
- Исходный STT-ответ с `platform:"vercel"` принимается: Amvera сохраняет формат ответа Vercel. Коды собственных ошибок прокси, например `upstream-network`, `upstream-invalid-response`, `busy` и `timeout`, сохраняются в диагностике.
- Ограничения Amvera: 4 000 000 байт, до 300000 мс записи. Основной ручной запрос ожидает ответ до 45 секунд; отдельный диагностический тест сохраняет прежний конечный тайм-аут.
- Автоматический выбор и резервные отправки остаются только для Render, Vercel и Netlify. Успешная ручная попытка Amvera не запоминается как автоматический резерв. Возврат в «Автоматически» исключает Amvera даже после предыдущего ручного выбора.
- Запись MediaRecorder, паузы и ручное завершение не менялись. Игровые объекты, анимации и языковой интерпретатор V3.0 не изменялись.

Amvera обслуживает только STT, без `/interpret`. Новый маршрут или перенаправление LLM не добавлялись. При выборе Amvera известные локальные команды V3.0 работают, но резервный LLM-разбор через этот сервер недоступен. Для проверки именно STT лучше начать с отдельного диагностического режима, который не выполняет игровые действия.

## Как обновить GitHub Pages

1. Обновите файлы существующего репозитория Korean Stickman из подготовленной папки или архива. Не добавляйте `.env`, ключи, `node_modules` и содержимое служебных папок. Файлы языкового слоя и backend не требуют исправлений для этой интеграции.
2. Проверьте, что в репозитории обновлён `.github/workflows/pages.yml`.
3. В GitHub откройте **Actions → Publish frontend to GitHub Pages → Run workflow** и выберите ветку с обновлением. Дождитесь завершения build и deploy. В **Settings → Pages** источником должен оставаться **GitHub Actions**.
4. Откройте `https://averanges.github.io/korean-stickman/` и выполните полное обновление страницы (Ctrl+F5).
5. В «Настройки голоса / тестирование» должна появиться четвёртая строка **Amvera** и пояснение «только ручной выбор».

Самостоятельная публикация в этой работе не выполнялась. Обновлять опубликованный Amvera-прокси, Render, Netlify или Vercel для подключения не требуется.

### Переменные GitHub Actions

**Новых обязательных переменных и секретов нет.** Адрес Amvera уже указан в сборке и workflow по умолчанию.

Необязательно можно добавить Repository variable:

```text
Settings → Secrets and variables → Actions → Variables → New repository variable
Name: AMVERA_API_BASE_URL
Value: https://korean-stickman-averanges.msk1.amvera.tech
```

Используйте именно публичный HTTPS-origin без `/transcribe`, параметров или ключей. Если переменная отсутствует, используется тот же готовый адрес. Остальные `API_BASE_URL`, `NETLIFY_API_BASE_URL`, `VERCEL_API_BASE_URL` оставьте прежними. `GROQ_API_KEY` в GitHub Pages не нужен.

Локальная сборка из папки проекта в PowerShell:

```powershell
$env:API_BASE_URL='https://korean-stickman.onrender.com'
npm run build:pages
```

Результат — папка `dist`, только публичные файлы. Ресурсы сохраняют относительные пути для `/korean-stickman/`. Для обычной публикации через существующий workflow вручную загружать `dist` не нужно.

## Первая ручная проверка аудио

Проверяйте на опубликованной странице GitHub Pages. С локальной страницы `localhost` Amvera может законно отклонить CORS: разрешён только `https://averanges.github.io`.

1. Откройте «Настройки голоса / тестирование», нажмите «Проверить серверы». У Amvera ожидаются «Прокси OK», «STT готов», «Vercel HTTP 200».
2. В разделе **«Тест STT без игровых действий»** выберите **Amvera**.
3. Нажмите «Записать тестовую фразу», произнесите `안녕하세요`, затем нажмите кнопку второй раз для отправки.
4. Проверьте текст в результате и сервер Amvera в отчёте. Параметры героя и комната при этом не меняются.
5. Повторите тест с `저는`, паузой 4 секунды и `러시아 사람이에요`. Запись должна ждать второго нажатия.
6. При необходимости сохраните ту же тестовую запись в памяти и явно отправьте её Vercel для сравнения, выбрав Vercel и нажав «Отправить ту же запись выбранному серверу». Автоматической повторной отправки Amvera нет.
7. После удачного диагностического теста можно выбрать **Amvera** в основном поле «Голосовой сервер» и попробовать обычный микрофон игры. В ручном режиме ошибка Amvera не переключает запись на другой сервер.
8. Нажмите «Скопировать отчёт», если нужен разбор ошибки. Перед передачей отчёта просмотрите содержащуюся в нём транскрипцию.
9. Верните основной выбор в **«Автоматически»**: снова используются только три прежних сервера.

## Выполненные проверки

- 9 новых автоматических тестов: регистрация четвёртого сервера, готовность upstream, ручной выбор, исключение из автоматического выбора и истории успехов, отсутствие автоматической повторной отправки, исходное аудио и ответ Vercel, коды ошибок и отчёт, сборка Pages и замена публичного адреса.
- Полная регрессия: 297 тестов прошли, включая ранее существующие проверки игры, интерпретатора и STT.
- Опубликованный Amvera `/health` проверен запросом с Origin GitHub Pages: HTTP 200, `upstream.sttReady:true`, HTTP Vercel 200.
- Реальный OPTIONS `/transcribe`: HTTP 204, `Access-Control-Allow-Origin: https://averanges.github.io`, разрешены POST и OPTIONS.
- Реальная запись с устройства ученика и доступность из конкретной сети России без VPN в этой работе не проверялись. Аудио на опубликованную Amvera автоматически не отправлялось.

Основная проверка тестов:

```sh
node --test --test-concurrency=2 tests/*.test.js
```
